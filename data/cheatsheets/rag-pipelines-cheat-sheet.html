What is RAG?
📚 RAG is like giving an LLM an open-book exam. Instead of relying only on what it memorised during training, it searches a knowledge base for relevant passages, then uses those passages to answer the question. The answer is grounded in your specific documents — not just general knowledge.

RAG = Retrieval-Augmented Generation. Retrieve relevant context from a document store, then augment the LLM prompt with that context before generating a response.

The 6-Step RAG Pipeline
1
Load — ingest documents (PDF, HTML, text)
2
Chunk — split into overlapping segments (~500 tokens)
3
Embed — convert each chunk to a vector using an embedding model
4
Store — save vectors in a vector database (Supabase pgvector, Pinecone, ChromaDB)
5
Retrieve — embed query, find top-k similar chunks by cosine similarity
6
Generate — inject retrieved chunks into LLM prompt, get grounded answer
What is an Embedding?
🗺️ An embedding is a list of numbers (a vector) that captures the meaning of text. Similar meanings → similar vectors → close together in vector space. "fever and chills" and "high temperature, shivering" will have very similar vectors even though the words differ.
RAG Code — Full Pipeline
Step 1–3: Chunk + Embed
import openai
from pathlib import Path

client = openai.OpenAI()

def chunk_text(text, chunk_size=500, overlap=50):
    # Split text into overlapping chunks
    words = text.split()
    chunks = []
    for i in range(0, len(words), chunk_size - overlap):
        chunk = " ".join(words[i : i + chunk_size])
        chunks.append(chunk)
    return chunks

def embed_text(text):
    # Get vector from OpenAI embedding model
    response = client.embeddings.create(
        model="text-embedding-3-small",
        input=text
    )
    return response.data[0].embedding  # list of floats

# Process a document
doc_text = Path("clinical_faq.txt").read_text()
chunks = chunk_text(doc_text)
embeddings = [embed_text(c) for c in chunks]
Step 4: Store in Supabase pgvector
# Supabase supports pgvector natively
from supabase import create_client

supabase = create_client(url, key)

for chunk, embedding in zip(chunks, embeddings):
    supabase.table("knowledge_base").insert({
        "content":   chunk,
        "embedding": embedding  # pgvector column
    }).execute()
Steps 5–6: Retrieve + Generate
def rag_answer(question, top_k=3):
    # Embed the question
    q_embedding = embed_text(question)

    # Find similar chunks via cosine similarity
    results = supabase.rpc("match_documents", {
        "query_embedding": q_embedding,
        "match_count": top_k
    }).execute()

    # Build context from retrieved chunks
    context = "\n\n".join(
        [r["content"] for r in results.data]
    )

    # Inject context into prompt
    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[{
            "role": "system",
            "content": "Answer using only the context below."
        }, {
            "role": "user",
            "content": f"Context:\n{context}\n\nQuestion: {question}"
        }]
    )
    return response.choices[0].message.content

Vector Similarity — Cosine
import numpy as np

def cosine_similarity(a, b):
    # Measures angle between two vectors
    # 1.0 = identical direction (same meaning)
    # 0.0 = perpendicular (unrelated)
    # -1.0 = opposite
    return np.dot(a, b) / (
        np.linalg.norm(a) * np.linalg.norm(b)
    )

Master Interview Answers
🎤 Q: "What is RAG and how does it work?"
RAG stands for Retrieval-Augmented Generation. Instead of asking an LLM to answer from memory alone, you first search a knowledge base for relevant documents, then inject those documents into the prompt so the LLM answers based on real, specific information. The pipeline: chunk documents, embed each chunk as a vector, store in a vector database, embed the query, retrieve top-k similar chunks by cosine similarity, then generate an answer grounded in those chunks. I built this in MediLens using Supabase pgvector for the clinical FAQ system.
✅ One-line summary RAG = retrieve relevant chunks from vector DB → inject into LLM prompt → generate grounded answer. Embeddings = text → vector of numbers capturing meaning. Cosine similarity finds closest chunks. Supabase pgvector = vector DB you already use. Better than fine-tuning for dynamic knowledge that updates frequently.
