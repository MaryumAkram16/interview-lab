List — Ordered, Mutable
📋 A list is like a to-do list — ordered, changeable, allows duplicates. You can add, remove, and reorder items freely.
# Create
items = [1, 2, 3, "hello", True]

# Access — O(1) by index
items[0]    # 1  (first)
items[-1]   # True (last)
items[1:3]  # [2, 3] (slice)

# Modify
items.append(4)          # add to end O(1)
items.insert(0, "new")   # insert at index O(n)
items.remove(2)          # remove by value O(n)
items.pop()               # remove last O(1)
items.pop(0)              # remove first O(n)

# Search
2 in items   # O(n) — scans entire list
items.index(2)  # position of value

# Sort
items.sort()                    # in-place
sorted(items)                   # returns new
sorted(items, key=lambda x: -x) # custom
Tuple — Ordered, Immutable
📦 A tuple is a sealed box. You can see what's inside but can't change it. Faster than lists, hashable, used for fixed data.
# Create — parentheses or just commas
point = (10, 20)
coords = 1, 2, 3      # also a tuple
single = (42,)          # trailing comma needed!

# Access — same as list
point[0]   # 10

# Unpack — very Pythonic
x, y = point          # x=10, y=20
first, *rest = (1,2,3,4) # first=1, rest=[2,3,4]

# Tuple as dict key (list cannot!)
grid = {(0,0): "start", (1,1): "end"}

# Named tuple — readable tuple fields
from collections import namedtuple
Point = namedtuple("Point", ["x", "y"])
p = Point(3, 4)
print(p.x, p.y)   # 3  4
💡 Tuple vs List — when to choose Use tuple for data that should NOT change: coordinates, RGB values, database rows, function return of multiple values. Use list when you need to add/remove items.
Set — Unordered, Unique, Fast Lookup
🎯 A set is like a bag of unique stickers. No duplicates allowed. No guaranteed order. But checking "is this sticker in the bag?" is instant — O(1).
# Create
tags = {"python", "AI", "n8n"}
empty_set = set()       # NOT {} — that's a dict!
from_list = set([1,2,2,3])  # {1,2,3} dedup

# Add / Remove
tags.add("supabase")
tags.remove("n8n")      # KeyError if missing
tags.discard("n8n")     # safe — no error

# Membership — O(1) ← key advantage!
"python" in tags        # True, instant

# Set operations
a = {1, 2, 3}; b = {2, 3, 4}
a | b    # union        {1,2,3,4}
a & b    # intersection {2,3}
a - b    # difference   {1}
a ^ b    # symmetric diff {1,4}
✅ Best use of sets — O(1) deduplication Converting a list to a set removes duplicates instantly. Checking membership in a set is O(1) vs O(n) for a list. In your projects: deduplicating webhook event IDs, checking if a user already submitted.
Dict — Key-Value, Fast Lookup
📖 A dictionary is like a real dictionary — look up any word (key) and instantly get its definition (value). O(1) lookup by key.
# Create
user = {"name": "Maryum", "role": "AI Eng"}

# Access — safe vs unsafe
user["name"]               # KeyError if missing
user.get("age")            # None — safe
user.get("age", 0)        # 0 — default value

# Add / Update / Delete
user["city"] = "Lahore"   # add or update
user.update({"age": 27})  # merge dict
del user["city"]           # delete key
user.pop("age", None)      # safe delete

# Iterate
for k, v in user.items():   # key + value
    print(k, v)
for k in user.keys():      # keys only
for v in user.values():    # values only

# Dict comprehension
squares = {x: x**2 for x in range(5)}
# {0:0, 1:1, 2:4, 3:9, 4:16}

Special Dict Types
from collections import defaultdict, Counter, OrderedDict

# defaultdict — no KeyError on missing key
groups = defaultdict(list)
groups["fruits"].append("apple")  # no error

# Counter — count frequencies
words = ["a","b","a","c","a"]
counts = Counter(words)
# Counter({'a':3, 'b':1, 'c':1})
counts.most_common(2)  # top 2 items
Master Interview Answers
🎤 Q: "When would you use a set instead of a list?"
When I need O(1) membership checks or automatic deduplication. In my complaint management system I use a set of processed complaint IDs — checking if an ID was already handled is O(1) with a set vs O(n) scanning a list. Sets also make deduplication trivial: just convert the list.
🎤 Q: "What is the difference between a tuple and a list?"
Tuples are immutable — once created you can't change them — which makes them hashable and usable as dict keys. Lists are mutable. Tuples are slightly faster to create and access. I use tuples for fixed structured data like coordinates or function return values, and lists when I need to add or remove items.
✅ One-line summary List = ordered mutable O(n) lookup. Tuple = ordered immutable hashable. Set = unordered unique O(1) lookup. Dict = key-value O(1) lookup. Pick based on: do you need order? duplicates? fast lookup? mutability?
