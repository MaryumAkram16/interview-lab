Function Calling
🔧 Function calling lets the LLM say "I need to use a tool." You define available tools as JSON schemas. When the model decides it needs one, it returns a structured tool call instead of a text response. Your code executes the function, then sends the result back to the model.
How It Works — 4 Steps
StepWho ActsWhat Happens
1YouSend message + tool definitions (JSON schema)
2LLMReturns tool_call with function name + args
3YouExecute the real function with the args
4LLMReceives result, generates final response
Define Tools — JSON Schema
import openai, json

client = openai.OpenAI()

# Define available tools
tools = [{
    "type": "function",
    "function": {
        "name": "get_appointment_slots",
        "description": "Get available appointment slots for a doctor",
        "parameters": {
            "type": "object",
            "properties": {
                "doctor_id": {
                    "type": "string",
                    "description": "The doctor's ID"
                },
                "date": {
                    "type": "string",
                    "description": "Date in YYYY-MM-DD format"
                }
            },
            "required": ["doctor_id", "date"]
        }
    }
}]
Execute the Tool Call
# Step 1: Send message with tools
response = client.chat.completions.create(
    model="gpt-4o", tools=tools,
    messages=[{"role":"user",
               "content":"Book me with Dr. Smith tomorrow"}]
)

msg = response.choices[0].message

# Step 2: Check if model wants to call a tool
if msg.tool_calls:
    tool_call = msg.tool_calls[0]
    args = json.loads(tool_call.function.arguments)

    # Step 3: Execute real function
    slots = get_appointment_slots(**args)

    # Step 4: Send result back to model
    response2 = client.chat.completions.create(
        model="gpt-4o",
        messages=[
            {"role":"user", "content":"Book me with Dr. Smith"},
            msg,
            {"role":"tool", "tool_call_id": tool_call.id,
             "content": json.dumps(slots)}
        ]
    )
LangChain Basics
🔗 LangChain is a framework that chains LLM calls, tools, and memory together into pipelines. Instead of wiring everything manually, you declare what happens: prompt → LLM → output parser → next step.
Basic Chain — LCEL Style
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

# Define prompt template
prompt = ChatPromptTemplate.from_messages([
    ("system", "You are a triage assistant."),
    ("human", "Patient symptoms: {symptoms}")
])

# Build chain with | operator (LCEL)
llm   = ChatOpenAI(model="gpt-4o")
chain = prompt | llm | StrOutputParser()

# Run chain
result = chain.invoke({"symptoms": "fever and cough"})
print(result)
RAG Chain with Retrieval
from langchain_community.vectorstores import Chroma
from langchain_openai import OpenAIEmbeddings
from langchain_core.runnables import RunnablePassthrough

# Setup retriever
vectorstore = Chroma.from_documents(
    docs, OpenAIEmbeddings()
)
retriever = vectorstore.as_retriever(search_kwargs={"k":3})

# RAG prompt
rag_prompt = ChatPromptTemplate.from_template("""
Answer based only on the context below.
Context: {context}
Question: {question}
""")

# Full RAG chain
rag_chain = (
    {"context": retriever, "question": RunnablePassthrough()}
    | rag_prompt
    | llm
    | StrOutputParser()
)

answer = rag_chain.invoke("What are visiting hours?")

Master Interview Answers
🎤 Q: "What is function calling in LLMs?"
Function calling lets an LLM request external actions instead of just generating text. You define available functions as JSON schemas describing their name, purpose, and parameters. When the model decides it needs real-world data, it returns a structured tool_call object instead of prose. Your code executes the actual function, then sends the result back to the model so it can incorporate it into the final response. I use this in MediLens for real-time appointment booking — the LLM decides when to call the calendar API.
🎤 Q: "When would you use LangChain vs the raw OpenAI API?"
LangChain is great for rapid prototyping — it has built-in retrievers, memory, and chain syntax that reduces boilerplate. For production systems where I need fine control over retry logic, error handling, and cost optimisation, I prefer the raw API. In my n8n workflows I use the raw API because n8n's HTTP node gives me full control over the request, and I can see exactly what's being sent without LangChain's abstraction layer hiding it.
✅ One-line summary Function calling = LLM returns structured tool_call → your code executes → send result back → LLM generates final response. Define tools as JSON schemas. LangChain = chain prompt | llm | parser with built-in RAG support. Use raw API for production control, LangChain for rapid prototyping.
