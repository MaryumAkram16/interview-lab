Hugging Face — Core Usage
Pipeline — Quickest Way
from transformers import pipeline

# Sentiment analysis
classify = pipeline(
    "sentiment-analysis",
    model="distilbert-base-uncased-finetuned-sst-2-english"
)
print(classify("The service was excellent!"))
# [{'label': 'POSITIVE', 'score': 0.9998}]

# Text generation
generate = pipeline("text-generation", model="gpt2")
print(generate("The hospital triage system", max_new_tokens=50))

# Named Entity Recognition
ner = pipeline("ner", aggregation_strategy="simple")
print(ner("Dr. Maryum works at Lahore General Hospital"))
Load Model + Tokenizer Manually
from transformers import AutoTokenizer, AutoModel
import torch

model_id = "distilbert-base-uncased"
tokenizer = AutoTokenizer.from_pretrained(model_id)
model     = AutoModel.from_pretrained(model_id)

# Tokenize text
inputs = tokenizer(
    "Patient has fever and cough",
    return_tensors="pt",
    truncation=True,
    max_length=512
)

# Get embeddings (no gradient needed)
with torch.no_grad():
    outputs = model(**inputs)

# CLS token = sentence embedding
embedding = outputs.last_hidden_state[:, 0, :]
print(embedding.shape)  # [1, 768]

Tokenization Deep Dive
✂️ Tokenization splits text into subword pieces. "playing" might become ["play", "##ing"]. The model never sees raw text — only token IDs (integers). Different models use different tokenizers — always use the tokenizer paired with the model.
from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("gpt2")

text = "Tokenization splits text into pieces"
tokens = tokenizer.tokenize(text)
ids    = tokenizer.encode(text)

print(tokens)
# ['Token', 'ization', 'Ġsplits', 'Ġtext', ...]
print(ids)
# [30642, 1634, 26291, 2420, ...]

# Decode back to text
print(tokenizer.decode(ids))
# "Tokenization splits text into pieces"

# Batch tokenize with padding
batch = tokenizer(
    ["First sentence", "Second longer sentence here"],
    padding=True,
    truncation=True,
    max_length=128,
    return_tensors="pt"
)

Master Interview Answers
🎤 Q: "What is the difference between an encoder-only and decoder-only model?"
Encoder-only models like BERT process the entire input bidirectionally — they see all tokens at once. This makes them excellent for understanding tasks like classification, NER, and embeddings. Decoder-only models like GPT generate text left-to-right — each token can only attend to previous tokens. This makes them ideal for generation tasks like chatbots and code completion. Encoder-decoder models like T5 combine both for sequence-to-sequence tasks like translation.
🎤 Q: "What is a tokenizer and why does it matter?"
A tokenizer converts raw text into the integer IDs that a model actually processes. It uses subword tokenization — splitting words into frequent pieces so the vocabulary stays manageable while handling rare words. You must always use the exact tokenizer paired with your model — different models have different vocabularies and special tokens. Using the wrong tokenizer produces garbage input IDs and garbage output.
✅ One-line summary Encoder-only (BERT) = understanding/classification. Decoder-only (GPT) = generation. Encoder-Decoder (T5) = translation/summarization. Hugging Face pipeline = 2-line inference for any NLP task. Always use the tokenizer matched to the model. Check model card license before production use.
