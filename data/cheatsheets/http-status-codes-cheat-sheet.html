Status Code Groups
📬 Status codes are the server's way of telling you what happened. Think of them like a delivery status: 2xx = delivered, 3xx = moved, 4xx = your fault, 5xx = our fault.
2xx Success
CodeMeaningWhen you see it
200OKGET/PUT/PATCH succeeded
201CreatedPOST created a new resource
204No ContentDELETE succeeded, no body
3xx Redirection
CodeMeaningWhen you see it
301Moved PermanentlyURL changed forever
302Found (Temp redirect)Temporary new location
304Not ModifiedCached version is still valid
4xx Client Errors — Your Fault
CodeMeaningFix
400Bad RequestFix your request body/params
401UnauthorizedAdd/fix auth token
403ForbiddenAuthenticated but no permission
404Not FoundWrong URL or resource deleted
409ConflictDuplicate resource, version clash
422UnprocessableValid format, invalid data
429Too Many RequestsHit rate limit — back off!
5xx Server Errors — Their Fault
CodeMeaningAction
500Internal Server ErrorRetry with backoff
502Bad GatewayUpstream service failed
503Service UnavailableServer overloaded, retry
504Gateway TimeoutRequest took too long
🔑 Critical rule — 4xx vs 5xx retry logic NEVER retry 4xx errors — they won't fix themselves. The problem is in your request. ALWAYS retry 5xx errors (with backoff) — they are temporary server issues. Exception: never retry 429 immediately — wait for Retry-After header.
Python Error Handling
Basic requests Error Handling
import requests

def safe_api_call(url, headers):
    try:
        response = requests.get(
            url,
            headers=headers,
            timeout=10  # always set timeout!
        )
        # Raises HTTPError for 4xx and 5xx
        response.raise_for_status()
        return response.json()

    except requests.exceptions.HTTPError as e:
        status = e.response.status_code

        if 400 <= status < 500:
            # Client error — don't retry
            raise ValueError(f"Client error {status}: fix request")

        elif 500 <= status < 600:
            # Server error — safe to retry
            raise RuntimeError(f"Server error {status}: retry")

    except requests.exceptions.Timeout:
        raise TimeoutError("Request timed out")

    except requests.exceptions.ConnectionError:
        raise ConnectionError("Network unreachable")

def handle_auth_errors(response):

        # Not authenticated — refresh token
        new_token = refresh_access_token()
        return retry_with_token(new_token)

    elif response.status_code == 403:
        # Authenticated but no permission
        # Retrying won't help — user needs access
        raise PermissionError(
            "Access denied — check user permissions"
        )
Handling 429 Rate Limit
import time

def handle_rate_limit(response):
    if response.status_code == 429:
        # Check for Retry-After header
        retry_after = response.headers.get(
            "Retry-After", 60  # default 60s
        )
        print(f"Rate limited. Waiting {retry_after}s")
        time.sleep(int(retry_after))
        return True   # signal: retry the call
    return False
⚠️ Always set timeout= on every request Without a timeout, a hanging server can freeze your entire application forever. Set timeout=10 or timeout=(3, 10) (connect timeout, read timeout) on every single requests call.
Production Error Patterns
Complete Error Handler — Production Style
import requests, logging

logger = logging.getLogger(__name__)

def call_openai(prompt, api_key):
    try:
        resp = requests.post(
            "https://api.openai.com/v1/chat/completions",
            headers={"Authorization": f"Bearer {api_key}"},
            json={
                "model": "gpt-4o",
                "messages": [{"role":"user","content":prompt}]
            },
            timeout=30
        )
        resp.raise_for_status()
        return resp.json()

    except requests.exceptions.HTTPError as e:
        code = e.response.status_code
        if code == 401:
            logger.error("Invalid API key")
        elif code == 429:
            logger.warning("Rate limited by OpenAI")
        elif code >= 500:
            logger.error("OpenAI server error")
        raise

    except requests.exceptions.Timeout:
        logger.error("OpenAI request timed out")
        raise

    except requests.exceptions.ConnectionError:
        logger.error("Cannot reach OpenAI API")
        raise
In Your Projects
🏥 MediLens — Retell AI + Gemini calls Every external API call — Retell AI voice, Gemini LLM, Google Calendar — needs a try/except with timeout. A 503 from Gemini should trigger a retry. A 401 means the API key expired — alert immediately, don't retry silently.
🛒 Lumina — Shopify API Shopify returns 429 with a Retry-After header during flash sales. Your webhook handler should read that header and pause before retrying — not hammer the API and make it worse.
Master Interview Answers
🎤 Q: "What is the difference between 401 and 403?"
401 Unauthorized means the request has no valid authentication — the user hasn't logged in or the token is missing or expired. You should refresh the token and retry. 403 Forbidden means the user is authenticated but doesn't have permission to access that resource. Retrying won't help — the user needs to be granted access.
🎤 Q: "Should you retry a 404 error?"
No. 404 means the resource doesn't exist at that URL. Retrying will always return 404 — nothing will change. You should handle it by logging the error and notifying the caller. Only retry 5xx errors and 429, since those are temporary conditions that may resolve on the next attempt.
✅ One-line summary 2xx = success. 3xx = redirect. 4xx = client bug (don't retry except 429). 5xx = server bug (retry with backoff). Always set timeout. Use raise_for_status() to auto-raise on errors. Log 5xx, fix 4xx.
