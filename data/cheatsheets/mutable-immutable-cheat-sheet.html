The Core Concept
🪨 Immutable = carved in stone. Once created, the value can never change — Python creates a brand new object instead. 🧱 Mutable = wet clay. You can reshape it in place. The object stays at the same memory address while its contents change.
✅ IMMUTABLE
int, float, bool
str, bytes
tuple
frozenset

Cannot change after creation.
🔄 MUTABLE
list
dict
set
bytearray
custom objects
Can change in place.
Proof with id() — Memory Address
# id() returns the memory address of an object

# IMMUTABLE — new object created on change
x = "hello"
print(id(x))         # e.g. 140234567
x = x + " world"
print(id(x))         # DIFFERENT address!
# "hello" still exists in memory — x just
# points to a new string object

# MUTABLE — same object modified in place
my_list = [1, 2, 3]
print(id(my_list))    # e.g. 140298765
my_list.append(4)
print(id(my_list))    # SAME address!
# Same object, just contents changed
Integer Caching — Python Trick
# Python caches small integers (-5 to 256)
a = 100;  b = 100
print(a is b)   # True — same object!

a = 1000; b = 1000
print(a is b)   # False — different objects

# Use == for value, 'is' for identity
# is checks id(), == checks value
💡 == vs is — always confuse people in interviews == checks if two objects have the same value.
is checks if two variables point to the same object in memory.
Always use == for value comparison. Only use is for None checks.
Why Lists Can't Be Dict Keys
🔑 Dict keys must be hashable. To hash something, Python needs its value to stay constant — because the hash is used as the index. A list can change at any time, so its hash would change too, and Python would lose the value stored at that index forever. 
# ❌ Lists are unhashable
my_list = [1, 2]
try:
    print(hash(my_list))
except TypeError as e:
    print(f"Error: {e}") # Error: unhashable type: 'list'

# ✅ Tuples are hashable (if contents are immutable)
my_tuple = (1, 2)
print(hash(my_tuple)) # Prints an integer hash value

# ❌ List as dict key — TypeError!
my_dict = {}
my_dict[[1,2,3]] = "value"
# TypeError: unhashable type: 'list'

# ✅ Tuple as dict key — works!
my_dict[(1,2,3)] = "value"
print(my_dict[(1,2,3)])  # "value"

# ✅ Frozenset as dict key — works!
my_dict[frozenset([1,2,3])] = "value"

# Rule: only hashable (immutable) types
# can be dict keys or set members

The Dangerous Mutability Trap
# ❌ Classic bug — mutable default argument
def add_item(item, lst=[]):  # DON'T DO THIS
    lst.append(item)
    return lst

print(add_item(1))  # [1]
print(add_item(2))  # [1, 2] ← BUG!
# Same list object reused every call!

# ✅ Fix — use None as default
def add_item(item, lst=None):
    if lst is None:
        lst = []
    lst.append(item)
    return lst
⚠️ Mutable default arguments — a classic interview trap Default arguments are evaluated ONCE when the function is defined, not each time it's called. A mutable default like lst=[] is shared across all calls. Always use None as default for mutable types.
Copying — Shallow vs Deep
📋 Shallow copy = copy the folder but not the files inside. Deep copy = copy everything, files included. Matters when your list contains other lists. 
import copy

original = [[1, 2], [3, 4]]

# Assignment — same object, not a copy!
ref = original
ref[0].append(99)
print(original)   # [[1,2,99],[3,4]] ← changed!

# Shallow copy — new outer list,
# but inner lists still shared
shallow = original.copy()   # or list(original)
shallow[0].append(88)
print(original)   # inner list still affected!

# Deep copy — fully independent
deep = copy.deepcopy(original)
deep[0].append(77)
print(original)   # not affected ✅
Pass by Assignment — Functions
# Immutable — original not changed
def change_int(x):
    x = 100

n = 5
change_int(n)
print(n)  # still 5 — int is immutable

# Mutable — original IS changed
def change_list(lst):
    lst.append(99)

my_list = [1, 2]
change_list(my_list)
print(my_list)  # [1, 2, 99] — list mutated!
Master Interview Answers
🎤 Q: "What is the difference between mutable and immutable in Python?"
Mutable objects like lists and dicts can be changed in place — the same memory address holds updated contents. Immutable objects like strings and tuples cannot change — any "modification" creates a brand new object at a new address. You can verify this with id(). This distinction matters for dict keys, function arguments, and copying behaviour.
🎤 Q: "Why can't you use a list as a dictionary key?"
Dictionary keys must be hashable — Python hashes the key to find its storage slot. Hashing requires the value to stay constant. Lists are mutable, so their value can change after insertion, which would corrupt the dictionary's internal structure. Use a tuple instead — it's immutable and hashable.
✅ One-line summary Immutable = new object on change (str, int, tuple). Mutable = same object modified (list, dict, set). Only immutable types are hashable → dict keys + set members. Mutable default arguments in functions are a common bug — always use None.
