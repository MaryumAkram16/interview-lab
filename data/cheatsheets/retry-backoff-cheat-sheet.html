Retry Logic — When & When Not
📞 Retry is like redialing a busy number. But if the number doesn't exist (404), redialing forever makes no sense. Only redial for temporary problems — server overloaded (503), network blip (timeout), rate limit (429).

Simple Retry Loop
import time, requests

def retry_request(url, max_retries=3):
    for attempt in range(max_retries):
        try:
            resp = requests.get(url, timeout=10)
            resp.raise_for_status()
            return resp.json()

        except requests.exceptions.HTTPError as e:
            code = e.response.status_code
            if code < 500 and code != 429:
                raise  # 4xx — don't retry
            if attempt == max_retries - 1:
                raise  # last attempt — give up

        # Wait before next attempt
        wait = 2 ** attempt   # 1s, 2s, 4s
        time.sleep(wait)

    raise RuntimeError("Max retries exceeded")
Exponential Backoff + Jitter
🌊 Exponential backoff is like waves on a beach — each retry waits twice as long as the previous one. Jitter adds a random wobble so 1000 clients don't all retry at the exact same second and crash the server again.
The Backoff Formula

wait = base × 2^attempt + random_jitter

Attempt 0→~1s (1 × 2⁰ + jitter)
Attempt 1→~2s (1 × 2¹ + jitter)
Attempt 2→~4s (1 × 2² + jitter)
Attempt 3→~8s (1 × 2³ + jitter)
Max cap→60s (never wait more)
Full Implementation with Jitter
import time, random, requests

def exponential_backoff(
    url,
    max_retries=4,
    base_delay=1,
    max_delay=60
):
    for attempt in range(max_retries):
        try:
            resp = requests.get(url, timeout=10)
            resp.raise_for_status()
            return resp.json()

        except (requests.exceptions.HTTPError,
                requests.exceptions.Timeout,
                requests.exceptions.ConnectionError) as e:

            if hasattr(e, 'response') \
               and e.response is not None \
               and e.response.status_code < 500 \
               and e.response.status_code != 429:
                raise  # 4xx — don't retry

            if attempt == max_retries - 1:
                raise  # exhausted retries

            # Exponential backoff with jitter
            wait = min(
                base_delay * (2 ** attempt)
                + random.uniform(0, 1),
                max_delay
            )
            print(f"Attempt {attempt+1} failed. Waiting {wait:.1f}s")
            time.sleep(wait)
💡 Why jitter matters Without jitter: if 500 clients all get rate-limited at time T, they all retry at T+2s, T+4s, T+8s — creating thundering herd waves that keep crashing the server. With jitter: each client waits a slightly different time, spreading the load evenly.

Circuit Breaker Pattern
⚡ A circuit breaker is like your home's fuse box. When something goes badly wrong (too many failures), it trips open and stops all requests for a cooldown period. This prevents hammering a failing service and gives it time to recover.
Circuit Breaker States
StateBehaviour
CLOSEDNormal — requests pass through
OPENTripped — all requests fail fast, no calls made
HALF-OPENTesting — one request allowed through to check recovery
import time

class CircuitBreaker:
    def __init__(self, failure_threshold=5,
                       reset_timeout=60):
        self.failures = 0
        self.threshold = failure_threshold
        self.reset_timeout = reset_timeout
        self.state = "CLOSED"
        self.opened_at = None

    def call(self, func, *args):
        if self.state == "OPEN":
            elapsed = time.time() - self.opened_at
            if elapsed < self.reset_timeout:
                raise RuntimeError("Circuit OPEN")
            self.state = "HALF-OPEN"

        try:
            result = func(*args)
            self.failures = 0
            self.state = "CLOSED"
            return result
        except Exception:
            self.failures += 1
            if self.failures >= self.threshold:
                self.state = "OPEN"
                self.opened_at = time.time()
            raise
Master Interview Answers
🎤 Q: "What is exponential backoff and why use it?"
Exponential backoff means each retry waits twice as long as the previous one — 1s, 2s, 4s, 8s. This gives the failing server increasing time to recover instead of being hammered by constant retries. I add jitter — a small random amount — to each wait time to prevent thundering herd, where hundreds of clients all retry at exactly the same moment and overwhelm the server again.
🎤 Q: "What is a circuit breaker and when would you use it?"
A circuit breaker tracks consecutive failures to an external service. When failures exceed a threshold, it trips open and stops sending requests for a cooldown period — failing fast instead of waiting for timeouts. After the cooldown it allows one test request through. If that succeeds, it closes again. I'd use it in MediLens for the Retell AI voice service — if Retell is down, fail immediately rather than making patients wait 30 seconds for every timeout.
✅ One-line summary Retry 5xx and timeouts only. Use exponential backoff: wait = base × 2^attempt + jitter. Cap max wait at 60s. Use tenacity library in production. Circuit breaker = fail fast after N failures, recover after cooldown.
