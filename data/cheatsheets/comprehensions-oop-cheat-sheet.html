Comprehensions
🏗️ A comprehension is a one-line factory: "build me a list/dict/set by running this operation on every item, optionally filtered by a condition." Cleaner and faster than a for loop.
List Comprehension
# Pattern: [expression for item in iterable if condition]

# Basic — square every number
squares = [x**2 for x in range(5)]
# [0, 1, 4, 9, 16]

# With filter — only even numbers
evens = [x for x in range(10) if x % 2 == 0]
# [0, 2, 4, 6, 8]

# Transform strings
names = ["maryum", "ali", "sara"]
caps = [n.capitalize() for n in names]
# ["Maryum", "Ali", "Sara"]

# Nested — flatten a 2D list
matrix = [[1,2], [3,4], [5,6]]
flat = [x for row in matrix for x in row]
# [1, 2, 3, 4, 5, 6]
Dict & Set Comprehensions
# Dict comprehension
word_lengths = {w: len(w) for w in names}
# {"maryum": 6, "ali": 3, "sara": 4}

# Set comprehension — unique lengths
unique_lens = {len(w) for w in names}
# {3, 4, 6}

# Generator expression (lazy, memory efficient)
total = sum(x**2 for x in range(1000000))
# () not [] — doesn't build full list in memory
Lambda Functions
# Lambda = small anonymous one-line function
# Pattern: lambda args: expression

double = lambda x: x * 2
print(double(5))   # 10

# Most common use — sorting by key
users = [
    {"name": "Ali",    "age": 25},
    {"name": "Maryum", "age": 27},
    {"name": "Sara",   "age": 22},
]
sorted(users, key=lambda u: u["age"])
# Sara (22), Ali (25), Maryum (27)

# With filter() and map()
nums = [1,2,3,4,5]
evens  = list(filter(lambda x: x%2==0, nums))
doubled = list(map(lambda x: x*2, nums))
💡 Comprehension vs for loop — when to use which Use comprehension for simple transforms and filters — it's faster and more Pythonic. Use a regular for loop when logic is complex, multi-line, or needs error handling inside. Never sacrifice readability for cleverness.
OOP — Classes & Objects
🏭 A class is a blueprint. An object is a thing built from that blueprint. A Car class defines what all cars have. Your specific red Toyota is an object — one instance of that blueprint.
Class Basics
class AIAgent:
    # Class variable — shared by ALL instances
    agent_type = "Language Model Agent"

    # __init__ = constructor, runs on creation
    def __init__(self, name, model):
        # Instance variables — unique per object
        self.name  = name
        self.model = model
        self.memory = []  # each agent has own memory

    # Instance method — uses self
    def respond(self, prompt):
        self.memory.append(prompt)
        return f"{self.name} ({self.model}): Processing..."

    # __str__ — controls print() output
    def __str__(self):
        return f"Agent: {self.name} | Model: {self.model}"

    # __repr__ — controls repr() / debugging
    def __repr__(self):
        return f"AIAgent('{self.name}', '{self.model}')"

# Create instances
agent1 = AIAgent("MediBot", "gpt-4o")
agent2 = AIAgent("LuminaBot", "gemini")

print(agent1)           # Agent: MediBot | Model: gpt-4o
print(agent1.respond("hello"))
Inheritance
# Child class inherits from parent
class VoiceAgent(AIAgent):  # inherits AIAgent

    def __init__(self, name, model, voice_id):
        # Call parent __init__ first
        super().__init__(name, model)
        self.voice_id = voice_id  # extra attribute

    # Override parent method
    def respond(self, prompt):
        base = super().respond(prompt)
        return f"{base} [Voice: {self.voice_id}]"

# Usage
lumina = VoiceAgent("Lumina", "gpt-4o", "voice_01")
print(isinstance(lumina, VoiceAgent))  # True
print(isinstance(lumina, AIAgent))     # True!
✅ super() — always call it in child __init__ super().__init__(...) runs the parent class constructor, setting up all the parent's attributes. If you forget it, the child object won't have the parent's instance variables.

# Example — __len__ and __eq__
class WorkflowPipeline:
    def __init__(self, steps):
        self.steps = steps

    def __len__(self):
        return len(self.steps)

    def __eq__(self, other):
        return self.steps == other.steps

pipeline = WorkflowPipeline(["triage","schedule"])
print(len(pipeline))  # 2
@staticmethod vs @classmethod
class Agent:
    agent_count = 0

    # @classmethod — access/modify class state
    # receives cls (the class itself) not self
    @classmethod
    def get_count(cls):
        return cls.agent_count

    # @staticmethod — utility, no self or cls
    # just a regular function in the class namespace
    @staticmethod
    def validate_model(model_name):
        return model_name in ["gpt-4o", "gemini"]

print(Agent.validate_model("gpt-4o"))  # True
Master Interview Answers
🎤 Q: "What is the difference between a class variable and an instance variable?"
A class variable is defined at the class level and shared by all instances — changing it affects every object. An instance variable is defined in __init__ using self and is unique to each object. In my AIAgent class, agent_type is a class variable shared by all agents, while name and model are instance variables unique to each agent.
🎤 Q: "When would you use a list comprehension vs a for loop?"
List comprehensions are best for simple, readable one-line transforms — filtering a list, mapping a function, or building a new collection. I use regular for loops when the logic spans multiple lines, needs error handling inside, or involves complex state. Readability always comes first — a comprehension that needs a comment to explain is better written as a loop.
✅ One-line summary Comprehensions: [expr for x in iterable if cond] — clean, fast, Pythonic. Classes: blueprint for objects. __init__ sets instance state. super() calls parent constructor. Dunder methods make objects behave like built-ins.
